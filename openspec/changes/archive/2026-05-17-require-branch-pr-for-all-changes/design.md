## Context

現在の `general.md` は「ブランチ名: `{issue番号}-{概要}`」の命名規則を定義しているが、「すべての変更はブランチを切る」という明示的なルールが存在しない。その結果、小さなドキュメント修正が直接 main に push されるケースが起きている。

## Goals / Non-Goals

**Goals:**
- `general.md` のブランチ・PR 運用セクションに「ドキュメント変更を含む全変更はブランチ経由・PR マージ」を明記する
- 例外（緊急 hotfix など）の有無を明確にする

**Non-Goals:**
- GitHub の branch protection ルール設定（リポジトリ設定の変更は対象外）
- CI/CD パイプラインの変更

## Decisions

**変更対象ファイル: `.claude/rules/general.md` のみ**

ルールは `general.md` の「ブランチ・Issue・PR の運用」セクションに追記する。`CLAUDE.md` は `general.md` を参照する構成になっているため、`general.md` の更新のみで十分。

**例外なし（原則禁止）**

ドキュメント変更であっても例外を設けず「原則として」という表現でルールを明記する。緊急時の判断は開発者の裁量に委ねるが、デフォルトはブランチ + PR とする。

## Risks / Trade-offs

- [小さなドキュメント修正にブランチが必要] → 運用コストが若干上がるが、変更履歴・意図の明文化というメリットがある
- [ルールを知らずに直接 push するリスク] → `general.md` に明記することで認知を促す（branch protection は別途検討）

## Context

`AuthGuard.tsx:24-41` の `!loading && !session` 分岐は、本来「別タブでの signOut 等による受動的なセッション喪失」を検知して表示するフォールバックUI（PR #259 で追加）。しかし `AuthContext.signOut()` は `setSession(null)` → `router.replace("/login")` の順で処理するため、同一タブでの意図的なサインアウト時にも一瞬同じ分岐を通過する。この分岐は「セッションが切れました」という受動的喪失を前提にした文言になっており、意図的サインアウト時に表示されると事実と異なる（ユーザーが自分で操作した直後に「切れた」と言われる）。

ユーザーとの検討で、以下2案のうち文言変更案を採用した:
- (A) `signingOut` フラグで意図的サインアウト中はフォールバックUI自体を抑制する
- (B) 文言を中立化し、両方の文脈で成立する内容にする（採用）

(A) は `signOut()` が例外を投げた場合や `router.replace` のナビゲーションが中断された場合にフラグのリセットが行われず、フォールバックUIが永久に抑制されたままになるリスクがある。これは「一瞬誤ったメッセージが見える」より悪い失敗モード（セッションが本当に切れているのに何も表示されない）であり、そのリスクを回避するためのリセット漏れ対策自体に追加のテスト設計・状態機械の検証が必要になる。(B) は状態を一切追加しないため、この種のリスクが構造的に存在しない。

## Goals / Non-Goals

**Goals:**
- フォールバックUIの文言を、意図的サインアウト直後・受動的セッション喪失のどちらの文脈で表示されても事実として不自然にならない内容に変更する
- 既存の `auth-guard` capability の「フォールバックUIを表示する条件」（`loading===false && session===null`）自体は変更しない

**Non-Goals:**
- フラッシュ自体（フォールバックUIが一瞬描画されること）の解消。今回は文言の正確性のみを扱う
- `signingOut` 相当の状態管理の追加
- `AuthContext.signOut()` の `setSession`/`router.replace` の順序変更

## Decisions

- **新しい文言**: 「セッションが切れました。」という確定的な事実主張を削除し、「ログインが必要です。」+「ログイン画面へ」ボタンのような、状態の原因を特定しない中立的な文言にする。原因（サインアウトした／セッションが切れた）を問わず成立する
- **既存テスト（`AuthGuard.test.tsx` の `/セッションが切れました/` アサーション）は新文言に更新する**。表示条件（`loading===false && session===null` で表示、`loading===true` では表示しない）を検証するテストの構造自体は変更しない
- **`auth-guard` spec の該当 Requirement 名・本文を「受動的な」という限定を外した中立的な記述に更新する**

## Risks / Trade-offs

- [Risk] 文言を曖昧にしすぎると、本当にセッションが切れた場合にユーザーが状況を理解しにくくなる → Mitigation: 「ログインが必要です」等、次に取るべき行動（再ログイン）は明確に伝える。原因の断定だけを避ける
- [Trade-off] フラッシュ自体は残る（意図的サインアウト時も一瞬フォールバックUIが見える）。将来的にフラッシュ自体の解消が必要になった場合は、別 Issue として `signingOut` 相当の状態管理をリセット漏れ対策込みで改めて設計する
